## 5. Decisions and landmines

- **Preserve `0.1.2` bytes.** Published filenames cannot be overwritten. Different
  contents under the same filename are a conflict, not something to skip blindly.
- **Use the saved retry set.** Twelve original artifacts are preserved under
  `.cache/publish-resume-0.1.2/`, verified against the committed-readable hash manifest.
  That directory is ignored local state; keep it on this machine until finished.
- **Do not run `build.sh` as a retry.** It deletes `dist/`, then rebuilds from the
  newer working tree. Those builds currently have development/local versions and
  are not the original release. Never upload a `+local` version to PyPI.
- **Do not run `publish.sh` as a retry.** It can invoke release gates, bump/version,
  commit/tag/push, rebuild and upload. The retry tool does none of those things.
- **Do not call `uv publish dist/*`.** `dist/` mixes the old release with local
  binary/native test wheels. The tool intentionally selects only the twelve
  pure-Python release artifacts.
- **No quota workarounds.** Do not change accounts, IPs or project names to bypass
  limits, and do not bump a version just because project creation is throttled.
- **Do not print credentials.** The tool accepts environment variables only and
  never reads credential files or records tokens in its JSON report.

## 6. Tool behavior and commands

Run from inside the `mcruft` repository. If starting in `mcruft-project`, first
`cd mcruft`. Python >=3.12 and the existing `uv` command are required; the tool adds
no dependencies. The user authorized resuming the prepared publication.

**First action tomorrow: preview, without credentials or mutation of PyPI.**

```bash
uv run python tools/resume_publish.py --dist .cache/publish-resume-0.1.2
```

Expected from the last check: eight `published`, four `pending`. A fresh check may
show fewer pending if an owner completed something meanwhile. Default output report:
`.cache/publish-resume.json`. Options: `--version X.Y.Z`, `--dist DIR`,
`--report FILE`, `--publish`. Nonstable versions and incomplete artifact sets fail.
HTTP errors other than 404 fail; they are not interpreted as missing projects.

Compare the saved artifact hashes with `docs/handoffs/pypi-0.1.2-artifacts.json`
before uploading. If files are missing, recover the originals from `dist/` or an
owner-preserved copy and check their hashes; do not rebuild the current source as
`0.1.2`. Published originals can be downloaded from their PyPI JSON URLs. The four
unpublished files require the preserved local copies.

If credentials are already exported, no credential-file load is necessary. Otherwise,
the existing project convention is to load the owner's environment privately:

```bash
set +x
if [[ -z "${UV_PUBLISH_TOKEN:-${PYPI_TOKEN:-}}" && -f "$HOME/.env" ]]; then
  source "$HOME/.env" >/dev/null 2>&1
fi
export UV_PUBLISH_TOKEN="${UV_PUBLISH_TOKEN:-${PYPI_TOKEN:-}}"
```

Never display the environment, `.env` contents or token value. The tool refuses an
upload without a token. Then make one bounded attempt:

```bash
uv run python tools/resume_publish.py --dist .cache/publish-resume-0.1.2 --publish
```

The tool checks hashes again, calls `uv publish` once for pending files with
`--check-url`, a fixed PyPI endpoint, `--no-config`, `UV_HTTP_RETRIES=0` and a
60-second HTTP timeout. uv stops on the first error. After the invocation, the
tool re-queries PyPI and records which hashes now match, including partial success.
It never automatically loops or sleeps. A failed post-upload lookup is an uncertain
verification result: use preview to reconcile it before any subsequent upload.
